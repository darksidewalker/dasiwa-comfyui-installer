# AMD ROCm Support Implementation Plan

**Goal:** Add a guarded native AMD installation path on Windows and Linux without system-wide runtime installs or CUDA-only extensions.

**Architecture:** Use AMD's stable multi-architecture ROCm 10.0 wheel index, pinned torch/vision/audio versions, and GPU-specific device extras. Reject unsupported hardware/Python/platform selections before wipe, checkout or runtime migration. Preserve existing update ABI. Verify the installed AMD backend with a real GPU operation. Keep CUDA-only extension controls unavailable on other vendors.

**Tech stack:** Go installer, embedded HTML/JS, managed uv/CPython, ROCm/PyTorch.

## Design decisions / constraints

- Keep Python 3.12 default: AMD publishes verified Windows wheels for both 3.12 and 3.13; don't mutate existing update ABI or force a global Python upgrade.
- Initial supported model mapping is deliberately explicit, not broad RX-family guessing: desktop RX 6800/6900/6950 (gfx1030), RX 7600 (gfx1102), RX 7700 XT/7800 XT (gfx1101), RX 7900 XT/XTX (gfx1100), RX 9060 (gfx1200), RX 9070 (gfx1201), relevant Radeon PRO and Strix Halo models. Explicit recognized gfx identifiers can disambiguate OS-provided names. Reject unknown/mismatched targets; do not use HSA overrides automatically.
- Platform requirements: Linux x86_64; Windows x86_64 Windows 11 with sufficiently recent AMD driver (ROCm 10.0 matrix: Windows 11 25H2 / Adrenalin 26.8.1). Check what is reliably detectable without elevation; document any prerequisite that cannot be verified reliably.
- Current AMD package set: `torch[device-<target>]==2.13.0+rocm10.0.0`, `torchvision[device-<target>]==0.28.0+rocm10.0.0`, `torchaudio==2.11.0.2+rocm10.0.0`; index `https://stable.repo.amd.com/rocm/whl-next/`. Verify Linux as well before adopting universally.
- Sage/Radial/Flash are the existing CUDA-specific installer implementations, not a claim that no AMD attention implementation exists. Backend rejects incompatible selected extensions before mutation; UI disables and unchecks them.
- ComfyUI core compatibility does not certify every bundled custom node or every FP8 workflow. Preserve actionable node warnings; do not advertise feature parity.
- No scripts added, no direct pip calls, no runtime config.json mutation, no commits/pushes without user permission.
- Keep all scratch caches/build probes under `$TMPDIR`, not system /tmp.
